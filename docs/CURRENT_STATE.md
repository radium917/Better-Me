# Better Me 当前产品状态

更新时间：2026-09-21

## 1. 产品定位

Better Me 是一个轻量目标打卡社区。核心关系不是关注、好友或群组，而是“正在坚持相同目标的人”。产品鼓励低压力记录，不把断签定义为失败，并通过个人统计和同行内容提供持续反馈。

当前版本是可交互的前端 MVP，主要用于验证首次建档、目标创建、打卡发布、同行浏览和个人复盘流程。

## 2. 核心原则

1. 先有目标，再进入社区。
2. 记录真实行动，不以互动数量奖励积分。
3. 允许中断和重新开始。
4. 同目标内容优先，但不做复杂个性化推荐。
5. 个人目标与公共同行内容分离，不提供小组功能。

## 3. 用户流程

### 3.1 首次注册

1. 用户从启动页点击“开始使用”。
2. 进入注册/登录页，填写手机号和昵称。
3. 手机号格式正确后才能获取演示验证码。
4. 获取验证码后才可输入 4 至 6 位验证码。
5. 创建档案后进入“选择你的第一个目标”。
6. 用户按分类浏览目标模板并选择一个模板。
7. 设置个人目标名称、说明、执行频率和开始日期。
8. 创建目标后完成新手引导，使用 `replace` 进入首次打卡页。
9. 用户可填写文字、选择心情、从相册选择图片或直接拍照。
10. 发布后进入“同行”，新内容通过 URL 中的 `pin` 参数置顶。
11. 若暂不发布，返回按钮直接进入“我的”，不会返回目标设置页。

### 3.2 回访与重新登录

- 已登录且完成引导：启动页显示“继续坚持”，进入“同行”。
- 已登录但未完成引导：启动页显示“继续设置目标”，进入模板选择。
- 已完成引导但已退出登录：必须重新登录；登录后直接进入“同行”，不会重复首次引导。
- 未登录用户直接访问主功能或引导页，会被送回注册/登录页。

### 3.3 日常打卡

1. 从底部中央按钮或目标详情进入发布页。
2. 选择进行中的目标。
3. 输入文字和/或上传图片。
4. 可选当天心情。
5. 查看当前连续、累计和近 30 天进度。
6. 发布后进入同行动态并置顶本条内容。

## 4. 信息架构

### 一级导航

- 同行：综合动态及用户目标分类。
- 发布：底部中央主操作，发布页中隐藏底部导航。
- 我的：资料、勋章与个人目标。

### 二级页面

- 单目标同行动态
- 打卡详情与评论
- 目标汇总与历史打卡
- 积分与勋章
- 通知中心
- 编辑资料
- 设置与隐私
- 举报
- 黑名单

## 5. 功能现状

### 5.1 同行

- 展示所有未被拉黑用户的打卡。
- 顶部支持“全部”和我的目标模板筛选。
- 点击当前“同行”Tab 会滚动到顶部并刷新路由状态。
- 新发布内容由 `pin=<checkInId>` 精确置顶。
- 卡片显示作者、日期、目标类别、已坚持天数、图片或文字摘要。
- 支持点赞、评论、举报、拉黑；自己的内容支持删除。
- mock 数据包含跑步、早起、阅读和早睡等真实场景配图。

### 5.2 发布打卡

- 可在多个进行中目标之间切换。
- 正文最多 500 字。
- 支持六种心情：开心、平静、有动力、疲惫、挣扎、自豪。
- 支持相册选择和移动端后置摄像头拍照。
- 图片在浏览器端缩放、压缩并转成 JPEG data URL。
- 支持纯文字、纯图片或图文打卡。
- 同一周期内只有符合规则的首批打卡计为有效打卡。

### 5.3 我的

- 顶部展示头像、昵称、佩戴勋章、简介。
- 数据条展示积分、已获得勋章数和进行中目标数。
- 勋章栏支持点击佩戴或取消佩戴。
- 展示进行中、暂停和已结束目标。
- 默认最多同时进行 3 个目标，可用积分解锁第 4 个。

### 5.4 目标详情

- “汇总”和“历史打卡”两个 Tab。
- 汇总展示当前连续、历史最长、近 30 天完成率、累计次数。
- 最近 5 周按周一至周日排列。
- 每月 1 日显示 `M/D`，其余日期显示日号。
- 有打卡时展示心情 emoji；无心情时展示完成标记。
- 点击已打卡日期进入对应打卡详情。
- 历史打卡按时间倒序展示完整卡片。

### 5.5 积分与勋章

- 有效打卡和里程碑产生积分。
- 点赞、评论、提醒和重复发布不产生积分。
- 勋章墙每行 2 张卡片，完整展示名称、条件和获得状态。
- 已获得勋章可在“我的”页面佩戴。
- 积分兑换包含第 4 个目标名额和演示虚拟物品。

### 5.6 安全与设置

- 通知类别可独立开关，并可设置提醒时间。
- 支持举报内容、拉黑和解除拉黑。
- 支持退出登录与注销账号。
- 注销会清除当前浏览器中的个人数据并恢复 mock 数据。

## 6. 业务规则

### 6.1 有效打卡

- 每日目标：同一自然日仅一条打卡计为有效。
- 每周目标：同一自然周内，在目标次数上限以内的打卡计为有效。
- 同周期可继续发布内容，但重复内容不重复获得基础积分。
- 删除有效打卡后，积分与该周期有效性会按 store 逻辑重新处理。

### 6.2 连续记录

每日目标：

- 按自然日计算。
- 今天未打卡时允许从昨天开始向前计算。
- 遇到缺失日期即中断。

每周目标：

- 以周一为自然周起点。
- 已结束自然周达到设定次数才视为完成。
- 连续值累计达标周内的实际打卡次数。
- 过去某周不足目标次数时连续中断。
- 当前进行中的自然周不判定失败，并计入本周已有次数。

### 6.3 动态排序

排序优先级从高到低：

1. URL 指定的置顶打卡。
2. 与用户目标模板相同的内容。
3. 有完整正文或图片的内容。
4. 发布时间。

被拉黑用户的内容不会进入动态流。

## 7. 视觉与交互规范

- 主框架比例固定为 `390 / 844`，桌面最大高度 `844px`、最大视口高度 `92vh`。
- 手机端使用完整屏幕，不显示设备外框。
- 全局字体基准为 `15px`，避免低信息密度。
- 暖白背景、中性深色文字、低饱和绿色强调色。
- 卡片使用轻描边、浅阴影和不超过视觉需要的圆角。
- 标签和关键统计使用 `whitespace-nowrap`，避免窄屏换行。
- 图片卡片采用统一比例和 `object-cover`。
- 主要操作提供按压反馈；动态列表使用轻微渐入动画。

## 8. 数据与演示边界

- 所有业务状态通过 Zustand persist 写入 `localStorage`。
- 当前存储版本为 v3，迁移会刷新真实图片 mock 并清理旧 emoji 配图。
- 图片使用 data URL 保存，因此不适合大量或长期图片存储。
- mock 图片依赖指定的生成图片服务和网络连接。
- 没有真实短信服务、后端鉴权、云存储、跨设备同步、审核系统或支付。
- 第三方登录、小组、私信、群聊、关注、转发、热榜和排行榜均不在当前范围。
